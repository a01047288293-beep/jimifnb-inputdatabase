# 지미에프앤비 내부 운영실

연결 쇼핑몰: **www.jimifnb0901.com** (카페24 몰 ID `jimifnb0901`, 기본값으로 설정됨)

카페24 주문·출고·CS·매출, 제품 원가·마진(신제품 연구 파이프라인), 메타·구글·틱톡 광고와 자동 규칙을 한 화면에서 관리합니다.
Netlify에 배포하며, 서버 기능은 Netlify Functions, 데이터 저장은 Netlify Blobs를 씁니다. 별도 DB나 서버 비용이 없습니다.

## 들어 있는 기능

| 메뉴 | 하는 일 |
| --- | --- |
| 홈 | 오늘 매출·출고 대기·답변 안 한 문의·광고비·추정 이익, 14일 추이, 최근 변경 |
| 주문·출고 | 결제일 기준 주문 목록, 상태별 분류, 송장 입력(여러 건 한 번에) → 카페24 배송중 처리 |
| CS 문의 | 상품 Q&A·1:1 문의 중 답변 안 한 글, 답변 등록, (선택) AI 답변 초안 |
| 매출 분석 | 이전 기간·작년 대비, 일별 추이, 요일·시간대 분포, 결제수단·주문 경로, 객단가, 광고비·추정 이익 |
| 상품·재고 | 판매 순위와 순위 변화, 옵션별 판매, 일별 추이, 재고 경고(품절·안전재고·소진 예상일), 원가 연결 |
| 고객 분석 | 신규·재구매·비회원 비중, 재구매율과 재구매 간격, 구매 횟수 분포, 지역별 매출, 단골 20명 |
| 출고 운영 | 결제→출고 소요시간, 24·48시간 출고율, 출고 지연 목록, 취소·반품 사유와 상품, CSV 내려받기 |
| 제품·마진 | 7단계 신제품 파이프라인, 배합·시생산 수율·포장·배송비로 1개 원가, 마진율, 손익분기 ROAS, 채널 비교, 민감도 |
| 광고 | 3개 매체 캠페인 통합 표, 켜기/끄기, 일 예산 변경, 캠페인 ↔ 제품 연결, 손익분기 판정 |
| 자동 규칙 | 조건(광고비·구매·ROAS·손익분기 대비 ROAS)에 따라 끄기·켜기·예산 증감. 15분마다 실행, 모의 실행 기본 |
| 변경 이력 | 누가 언제 무엇을 바꿨는지 (사람·자동 규칙 모두) |
| 설정·연동 | 연결 상태, 카페24 연결 버튼, 자동 규칙 안전장치(하루 최대 횟수·최소 예산·변경 한도) |

키를 등록하기 전에는 **데모 데이터**로 모든 화면이 동작합니다(화면에 "데모" 표시). 키를 등록한 영역부터 실제 데이터로 바뀝니다.

## 1. 배포하기 (처음 한 번)

1. GitHub에서 **비공개** 저장소를 새로 만듭니다 (예: `jimi-ops`). 이 폴더의 파일을 모두 올립니다. `.data` 폴더와 `node_modules`는 올리지 않습니다.
2. Netlify → **Add new site → Import an existing project → GitHub** → 저장소 선택. 빌드 설정은 `netlify.toml`에서 자동으로 읽습니다(빌드 명령 없음, 공개 폴더 `public`).
3. **Site configuration → Environment variables** 에 아래 두 개를 먼저 등록합니다.

   | 이름 | 값 |
   | --- | --- |
   | `ADMIN_PASSWORD` | 로그인 비밀번호 (8자 이상, 다른 곳에서 쓰지 않는 것) |
   | `SESSION_SECRET` | 아무 긴 임의 문자열 (32자 이상 권장) |

4. **Deploys → Trigger deploy** 로 다시 배포하고, 사이트 주소로 접속해 로그인합니다.
5. 도메인을 붙이려면 Netlify의 Domain management에서 추가합니다 (예: `ops.jimifnb0901.com`).

> 자동 수집(15분마다)은 실제 배포된 사이트에서만 돌아갑니다. 설정·연동 화면의 "지금 수집"으로 바로 실행할 수도 있습니다.

## 2. 카페24 연결

1. [카페24 개발자센터](https://developers.cafe24.com)에서 앱을 만듭니다.
2. 앱 설정의 **Redirect URI**에 `https://<사이트 주소>/api/cafe24/callback` 을 넣습니다 (설정·연동 화면에 정확한 주소가 나옵니다).
3. 권한: 주문 읽기/쓰기, 게시판 읽기/쓰기, 상품 읽기, 상점 읽기.
4. 발급된 값을 Netlify 환경변수에 등록하고 다시 배포합니다. 몰 ID(`jimifnb0901`)와 자사몰 주소는 이미 들어 있어 넣지 않아도 됩니다.

   | 이름 | 값 |
   | --- | --- |
   | `CAFE24_CLIENT_ID` | 앱의 Client ID |
   | `CAFE24_CLIENT_SECRET` | 앱의 Client Secret |

   자사몰 도메인(www.jimifnb0901.com)은 카페24 쪽 설정이라 이 시스템 배포와 서로 영향이 없습니다. 운영실은 별도 주소(예: `ops.jimifnb0901.com` 또는 Netlify 주소)로 엽니다.

5. 설정·연동 → **카페24 연결하기** → 카페24에서 권한 승인. 끝나면 "실제"로 표시됩니다.
   연결은 15분마다 자동으로 연장되므로 다시 할 필요가 없습니다(14일 넘게 사이트가 멈춰 있었다면 다시 연결).

선택 환경변수: `CAFE24_MALL_ID`·`SHOP_URL` (다른 몰에 쓸 때만), `CAFE24_CS_BOARDS` (문의 게시판 번호, 쉼표 구분. 비우면 이름에 "문의·Q&A"가 들어간 게시판), `CAFE24_CS_REPLY_MODE` (`reply` 답글 / `comment` 댓글).

## 3. 광고 매체 연결
| 매체 | Netlify 환경변수 | 받는 곳 |
|---|---|---|
| 메타 | `META_ACCESS_TOKEN`, `META_AD_ACCOUNT_ID` | 비즈니스 설정 → 시스템 사용자 → 토큰 생성 (권한 `ads_read`, `ads_management`, `business_management`, 만료 없음), 광고 계정 ID(숫자만) |
| 구글 | `GOOGLE_ADS_CLIENT_ID`, `GOOGLE_ADS_CLIENT_SECRET`, `GOOGLE_ADS_CUSTOMER_ID` (+MCC 경유 시 `GOOGLE_ADS_LOGIN_CUSTOMER_ID`) | Google Cloud 콘솔 → Google Ads API 사용 설정 → OAuth 클라이언트(웹 애플리케이션). 등록 후 설정·연동의 **구글 Ads 연결하기** 버튼으로 승인 (갱신 토큰은 운영실이 저장) |
| 틱톡 | `TIKTOK_ACCESS_TOKEN`, `TIKTOK_ADVERTISER_ID` | 틱톡 비즈니스 개발자 앱 |

구글은 2026-09-10부터 접근 권한을 개발자 토큰이 아니라 Cloud 프로젝트의 액세스 수준(테스트 → 탐색기 → 기본)으로 판단합니다. 실제 광고 계정을 읽으려면 Cloud 콘솔 Google Ads API 페이지에서 **탐색기(Explorer) 이상**을 신청하세요. `GOOGLE_ADS_DEVELOPER_TOKEN`, `GOOGLE_ADS_REFRESH_TOKEN` 은 넣으면 쓰고 없어도 됩니다.
API 버전은 기본값(메타 v26.0, 구글 v25, 틱톡 v1.3)을 쓰며 `META_API_VERSION`, `GOOGLE_ADS_API_VERSION` 으로 바꿀 수 있습니다.

### 광고 분석 화면이 제대로 보이려면
- **메타**: 픽셀에서 `ViewContent`·`AddToCart`·`InitiateCheckout`·`Purchase` 이벤트가 잡혀야 퍼널이 채워집니다. 소재 썸네일·빈도는 같은 토큰으로 받아옵니다.
- **구글**: 구글 애즈 → 목표 → 전환에 '장바구니 담기', '결제 시작' 전환 액션을 등록해야 퍼널에 보입니다(없으면 해당 단계는 메타만 계산).
- **손익 판정**: 광고 관리에서 캠페인마다 제품을 연결해야 손익분기 ROAS 기준 코멘트가 붙습니다.
- **AI 종합 코멘트**(선택): `ANTHROPIC_API_KEY` 를 등록하면 광고 분석 상단에 버튼이 생깁니다. 숫자 요약만 보내며 고객 정보는 보내지 않습니다.

### AI 참모 (매출·광고비 의사결정)
- `ANTHROPIC_API_KEY` 를 등록하면 왼쪽 메뉴 **AI 참모**가 켜집니다. 최근 30일 매출, 최근 14일 광고(캠페인·소재·퍼널·제품 손익)를 보고 답하고, 필요하면 기간 보고서를 직접 조회합니다.
- 광고 끄기·켜기·예산 변경은 **제안 카드**로만 만들고, 대표가 **실행** 버튼을 눌러야 적용됩니다(설정의 최소 예산·최대 변경 폭 적용, 24시간 지나면 만료, 변경 이력에 "AI 참모 제안"으로 기록).
- 고객 이름·연락처·주소는 보내지 않고 합계 숫자만 보냅니다. 모델은 `ANTHROPIC_ADVISOR_MODEL` 로 바꿀 수 있습니다(기본 claude-sonnet-5-5).

## 4. 운영 시작 순서 (권장)

1. **제품·마진**에서 판매 중인 제품의 원가를 입력하고, 각 제품에 카페24 상품을 연결합니다.
2. **광고**에서 캠페인마다 해당 제품을 연결합니다 → 손익분기 판정이 나옵니다.
3. **자동 규칙**은 추천 규칙으로 시작하되 **모의 실행**으로 1주일 둡니다. 변경 이력의 "모의 실행" 기록이 맞는지 확인한 뒤 실제 실행으로 바꿉니다.
4. 안전장치: 하루 최대 20회, 한 번에 예산 최대 50%, 최소 일 예산 1만 원 (설정·연동에서 변경).

## 5. 첫 실제 연결 때 확인할 것

외부 API 문서로 요청 형식을 맞췄지만, 아래는 실제 계정에서 한 번 확인이 필요합니다. 결과가 다르면 환경변수로 조정합니다.

- **카페24 CS 답변 방식**: 답글(기본)이 게시판 정책상 안 되면 `CAFE24_CS_REPLY_MODE=comment`.
- **메타 구매 집계**: 기본은 `omni_purchase` → `purchase` → 픽셀 구매 순으로 하나만 씁니다. 광고관리자 숫자와 다르면 `META_PURCHASE_ACTION` 지정.
- **틱톡 지표 이름**: 구매 `complete_payment`, 구매 금액 `total_complete_payment_rate`. 다르면 `TIKTOK_PURCHASE_METRIC`, `TIKTOK_VALUE_METRIC`.
- **틱톡 예산 단위**: 원 단위로 보냅니다. 첫 예산 변경 후 틱톡 광고관리자에서 금액을 확인하세요.

## 6. 선택: AI 답변 초안

`ANTHROPIC_API_KEY` 를 등록하면 CS 화면에 "AI 답변 초안" 버튼이 생깁니다 (Anthropic API 사용료 별도). 모델은 `ANTHROPIC_MODEL` 로 바꿀 수 있습니다.
초안에 모르는 사실은 `[확인 필요]`로 표시되며, 이 표시가 남아 있으면 등록되지 않습니다.

## 7. 기타

- `DEMO_MODE=off` 로 두면 연결하지 않은 영역은 데모 대신 빈 화면이 됩니다.
- 고객 개인정보(연락처·주소)는 저장하지 않고, 구매자 이름은 가운데를 가려서 보여 줍니다.
- 모든 키는 Netlify 환경변수에만 넣습니다. 채팅·문서·GitHub에 올리지 마세요.

## 개발자용

```bash
npm install
npm run dev     # http://localhost:8888  (비밀번호 jimi-local-1234, 데모 모드, .data 폴더에 저장)
npm test        # 계산·규칙·API·외부 연동 형식 테스트 23개
```

폴더 구성: `public/` 화면(해시 주소 방식), `public/lib/margin.js` 원가 계산(화면·서버 공용), `netlify/functions/api.mjs` 모든 API, `netlify/functions/sync.mjs` 15분 자동 수집, `netlify/lib/` 연동·저장·규칙·분석.
